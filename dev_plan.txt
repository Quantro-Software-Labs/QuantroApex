1. Development Methodology
1.1 Chosen Model — Agile (Scrum), Solo Build
QuantroApex is built using Agile Scrum by a single technical founder, assisted by an AI coding agent. This combination replaces what would traditionally require a team of four to five developers while maintaining the discipline and quality a financial product demands.
Why this works for QuantroApex:
1. The founder owns the full stack — Flutter, Node.js, PostgreSQL — all MVP technologies
2. AI coding agents handle boilerplate, scaffolding, repetitive patterns, and test generation
3. Sprint structure provides discipline and prevents scope creep in a solo environment
4. Detailed product blueprint and design system give the AI agent precise context every time
5. Timeline compresses from a traditional 20 weeks to approximately 11 weeks

3. Design Approach — AI-Assisted, System-Driven
3.1 The Core Principle
Without a dedicated designer, consistency becomes the founder's responsibility and the design system becomes the tool that enforces it. An AI agent building screens one by one will drift — spacing varies, component styles diverge, tone shifts. A single, well-defined design system document prevents this entirely.
The rule: every screen the AI agent builds references the design system first.
Same tokens. Same components. Same rules. Every time. No exceptions.

3.3 Step 2 — Define Screen Specs Before Building
Before the agent builds any screen, the founder writes a plain-English screen spec. This takes 10 to 15 minutes per screen and dramatically improves the quality of the agent's output. The spec follows a consistent format.
Screen Spec Format:
Screen name and purpose — one sentence
Layout structure — how the screen is organised top to bottom
Components used — reference component library names exactly
Data displayed — what API data populates each element
Interactions — what taps, swipes, or inputs exist
States — empty state, loading state, error state
Quiet Confidence notes — any specific tone or restraint requirements for this screen
Example spec for the Home Dashboard:
Home Dashboard Screen Spec
Purpose: The first screen users see. Communicates portfolio status and Apex state with maximum calm.
Layout (top to bottom):
  1. Greeting line — "Good morning, [name]" in textSecondary colorMuted
  2. Portfolio value — textDisplay colorPrimary, bold, centred
  3. Today's movement — textBody, colorSuccess if positive, colorDanger if negative, no icons
  4. Apex Status widget — StatusBadge + one line of text in textSecondary
  5. Activity Snapshot — last 3 ActivityFeedEntry components, no header
  6. Primary action button — PrimaryButton, full width, contextual label
  7. Live/Simulation toggle — small, right-aligned, textCaption, never prominent
States: Loading — show skeleton placeholders, not spinners. Empty — no trades yet, show "Apex is monitoring."
Quiet Confidence: No colour fills on the portfolio value. No trend arrows. Numbers only.
3.4 Step 3 — Prompt the Agent Precisely
The quality of the agent's UI output is directly proportional to the precision of the prompt. A vague prompt produces a generic screen. A precise prompt produces a screen that reflects Quiet Confidence.
The prompt structure for every screen build:
Standard Screen Build Prompt Structure:
1. Reference the design system — "Use the QuantroApex design system. Colour tokens: [list]. Spacing tokens: [list]."
2. Reference the component library — "Use these existing components: [list relevant ones]."
3. Provide the screen spec — paste the full spec written in Step 2.
4. State the philosophy — "This screen follows the Quiet Confidence principle: calm, composed, no visual noise."
5. Specify what not to do — "No gradients, no heavy shadows, no animations beyond the defined motion tokens."
6. Request states — "Provide loading, empty, and error states for each data-dependent element."

Even with a design system, the agent can drift over multiple screens. Two scheduled consistency audits catch this before it compounds.
